السؤال الثاني: البنية العامة لتطبيقات الويب (الدرس 3-1)

13 درجة
  1. عرّف تطبيق الويب مع ذكر مثالين، ثم اشرح الطبقات الثلاث لتطبيق الويب موضحًا دور كل طبقة ومثالًا لها. [4 درجات]
  2. اشرح بالترتيب الخطوات الست لتعاون الطبقات الثلاث عندما يبحث مستخدم عن منتج في متجر إلكتروني. [3 درجات]
  3. علّل: لا يمكن للواجهة الأمامية وحدها أن تعرض نتائج بحث صحيحة. ثم بيّن: أي طبقة تجمع المدخلات؟ وأي طبقة تجد الإجابة؟ [2 درجة]
  4. قارن بين موقع مشاركة الفيديو وشبكة التواصل الاجتماعي من حيث دور كل طبقة. وما الذي يتغير من خدمة إلى أخرى مع أن البنية واحدة؟ [2 درجة]
  5. مكتبة مدرسية تريد تطبيق ويب لحجز الكتب ومتابعة الاستعارات السابقة: (أ) وزّع على الطبقات مع التعليل: نموذج الحجز – التحقق من توفر الكتاب – تخزين سجل الاستعارات. (ب) فتحت صفحة الحجز لكن لم تظهر أي كتب؛ ما الأجزاء التي قد تكون السبب؟ (ج) هل تنصح بتنظيم المسؤوليات في طبقات واضحة؟ برّر بسببين. [2 درجة]
✔️ نموذج الإجابة [13]

(1) [4] تطبيق الويب: تطبيق يُستخدم عادةً عبر متصفح الويب، وقد يكون بعضه قابلًا للتثبيت (فيديو، تسوق، بريد، خرائط).

  • الأمامية: يراها المستخدم ويتفاعل معها؛ تعرض وتستقبل المدخلات (شاشة البحث).
  • الخلفية: على الخادم؛ تعالج الطلبات وتطبّق القواعد (التحقق من الدخول).
  • قاعدة البيانات: تحفظ البيانات وتوفرها (سجل الطلبات).

(2) [3 – نصف درجة لكل خطوة] تستقبل الأمامية كلمات البحث ← ترسلها للخلفية ← تطلب الخلفية المنتجات المطابقة من قاعدة البيانات ← تعيد قاعدة البيانات النتائج ← تجهّزها الخلفية وترسلها للأمامية ← تعرضها الأمامية على الشاشة.

(3) [2] لأن البيانات في قاعدة البيانات، والبحث فيها وتطبيق معاييره مهمة الواجهة الخلفية؛ فالأمامية تعرض وتجمع فقط. المدخلات تجمعها الأمامية، والإجابة تُوجد بمعالجة الخلفية لبيانات قاعدة البيانات.

(4) [2]

الطبقةموقع الفيديوشبكة التواصل
الأماميةشاشات تشغيل الفيديو والبحثالخط الزمني وشاشات النشر
الخلفيةالفيديوهات الموصى بها وتجميع المشاهداتالجمهور المستهدف والإشعارات
البياناتالفيديو والمستخدمون وسجل المشاهدةالمنشورات والمتابعة والرسائل

الذي يتغير: نوع البيانات، وقواعد المعالجة، والشاشات المعروضة؛ أما البنية فثابتة.

(5) [2] (أ) نموذج الحجز ← الأمامية؛ التحقق من توفر الكتاب ← الخلفية؛ سجل الاستعارات ← قاعدة البيانات. (ب) الخلفية أو قاعدة البيانات أو الاتصال بينهما، لأن الصفحة نفسها فتحت. (ج) نعم: يسهّل تحديد مكان الخطأ وإصلاحه، ويسمح بتعديل طبقة دون إعادة بناء الباقي.

السؤال الثالث: طرق اتصال تطبيقات الويب (الدرس 3-2)

14 درجة
  1. عرّف كلًّا من العميل والخادم مع مثال لكل منهما، ثم وضّح المقصود بنموذج الطلب والاستجابة. [2 درجة]
  2. قارن بين HTTP وHTTPS (التعريف – الحماية – شكل العنوان)، ثم علّل: يجب أن تستخدم صفحة تسجيل الدخول HTTPS. [3 درجات]
  3. ما المقصود بطريقة طلب HTTP؟ قارن بين GET وPOST مع مثالين لكل منهما، ثم حدد الأسلوب المناسب لكل من: تحميل سجل درجات الطالب – إرسال نموذج تسجيل الدخول. [3 درجات]
  4. ما المقصود برمز حالة HTTP؟ اشرح معنى 200 و404 و500، ثم: إذا استقبل المتصفح 404 فماذا يخبر المستخدم؟ ولماذا لا يكفي 500 وحده لمعرفة السبب؟ [3 درجات]
  5. عرّف API وصيغة JSON، ثم حدد في البيانات التالية جميع المفاتيح والقيم، وبيّن أي قيمة تمثل مصفوفة. [3 درجات]
    student.json

  "grade": 2,
  "subjects": ["Programming", "Math"],
  "passed": true

✔️ نموذج الإجابة [14]

(1) [2] العميل: برنامج أو جهاز يرسل طلبًا إلى خدمة أخرى (المتصفح). الخادم: يستقبل الطلبات ويعالجها ويعيد الاستجابات (خادم الويب). النموذج: يرسل العميل طلبًا ويعيد الخادم استجابة وفق قواعد بروتوكول مثل HTTP.

(2) [3]

المقارنةHTTPHTTPS
التعريفبروتوكول لتبادل الرسائل بين عميل وخادمHTTP عبر اتصال TLS آمن
الحمايةلا يحمي المحتوىيحمي السرية والسلامة ويصادق على الخادم
العنوانhttp://https://

التعليل: صفحة الدخول ترسل بيانات حساسة، وHTTPS يمنع المتجسس من قراءتها أو تعديلها ويتحقق من هوية الخادم.

(3) [3] طريقة طلب HTTP: معلومات في الطلب توضح نوع العملية المطلوبة. GET: لطلب مورد أو بيانات (عرض صفحة، نتائج البحث). POST: لإرسال بيانات ليعالجها الخادم (بيانات الدخول، محتويات نموذج). سجل الدرجات ← GET · نموذج الدخول ← POST.

(4) [3] رمز الحالة: رقم في الاستجابة يشير إلى نتيجة المعالجة. 200 نجاح · 404 المورد غير موجود بهذا العنوان · 500 خطأ داخلي في الخادم. عند 404 يُخبَر المستخدم أن الصفحة غير موجودة (عنوان خطأ أو صفحة محذوفة). 500 يخبر بوجود خطأ في جانب الخادم فقط ولا يحدد السبب التفصيلي.

(5) [3] API: قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر. JSON: صيغة نصية لتمثيل وتبادل البيانات المهيكلة بكائنات ومصفوفات وقيم بسيطة.

السؤال الرابع: أساسيات تقنية الواجهة الأمامية (الدرس 3-3)

13 درجة
  1. اشرح دور كل من HTML وCSS وJavaScript في بناء صفحة الويب مع التشبيه المناسب لكل منها بأجزاء المبنى، ثم بيّن: هل يجب أن تستخدم كل صفحة التقنيات الثلاث معًا؟ [4 درجات]
  2. ما المقصود بـ HTML الدلالي؟ اذكر أربعة من عناصره مع وظيفة كل عنصر، واشرح فائدتين لاستخدامه، ثم علّل: لا يضمن ظهور الصفحة في أعلى نتائج البحث. [3 درجات]
  3. عرّف التصميم المتجاوب، واذكر سبب الحاجة إليه، وما المقصود بنهج «الأولوية للجوال»؟ [2 درجة]
  4. ما المقصود بإطار العمل؟ وما فائدة استخدامه؟ وفرّق بين React وNext.js. [2 درجة]
  5. موقع إخباري: صعب القراءة على الهاتف، وقارئ الشاشة لا يفهم أجزاء الصفحة، وكل المحتوى والتنسيق والسلوك في ملف واحد بلا تنظيم. اقترح حلًّا لكل مشكلة مع التعليل. [2 درجة]
✔️ نموذج الإجابة [13]

(1) [4] HTML يحدد البنية ← هيكل المبنى. CSS يحدد المظهر ← الديكور. JavaScript يضيف السلوك والتفاعل ← الكهرباء والسباكة. ليس ضروريًا استخدام الثلاثة؛ يمكن HTML وحده أو معه CSS وJavaScript حسب الحاجة.

(2) [3] عناصر توضح وظيفة أجزاء الصفحة: header أعلى الصفحة، nav التنقل، main المحتوى الرئيسي، footer أسفل الصفحة. فائدتاه: إمكانية الوصول، وفهم محركات البحث. لا يضمن ترتيبًا أعلى لأنه يساعد على الفهم فقط.

(3) [2] التخطيط يُضبط تلقائيًا حسب حجم الشاشة؛ لأن المواقع تُفتح من أجهزة متنوعة. الأولوية للجوال: مراعاة الشاشات الصغيرة منذ بداية التصميم.

(4) [2] إطار العمل: بنية توفر مسبقًا وظائف ومكونات شائعة لتطوير أكثر كفاءة دون كتابة كل الكود من الصفر. React: مكتبة JavaScript لواجهات المستخدم من مكونات قابلة لإعادة الاستخدام. Next.js: إطار مبني على React يوفر التوجيه والعمل على الخادم والعميل.

(5) [2] الهاتف ← التصميم المتجاوب · قارئ الشاشة ← HTML الدلالي · الملف الواحد ← فصل HTML وCSS وJavaScript كلٌّ حسب دوره؛ لتسهيل التعديل واكتشاف الأخطاء.

السؤال الخامس: سؤال شامل يربط الوحدة كلها

5 درجات

ضغط طالب على زر «عرض نتيجتي» في موقع المدرسة من هاتفه، فظهرت النتيجة داخل جزء من الصفحة دون إعادة تحميلها كاملة. تتبّع ما حدث خطوة بخطوة من لحظة الضغط حتى ظهور النتيجة، مستخدمًا المصطلحات التالية:

العميل والخادمالطبقات الثلاثالبروتوكول المناسبطريقة الطلبرمز الحالةAPI و JSONدور JavaScriptالتصميم المتجاوب
✔️ نموذج الإجابة [5]
  1. الموقع مصمم بـ التصميم المتجاوب فيظهر الزر مناسبًا على شاشة الهاتف.
  2. تستقبل الواجهة الأمامية الضغطة، والعميل (المتصفح) يرسل طلب GET لأنه يسترجع بيانات.
  3. يُرسَل الطلب عبر HTTPS لأن النتيجة بيانات شخصية؛ فيحمي TLS سريتها وسلامتها.
  4. يستقبل الخادم الطلب عبر API، وتعالجه الواجهة الخلفية وتطلب النتيجة من قاعدة البيانات.
  5. يرد الخادم برمز 200 والنتيجة بصيغة JSON، فتحدّث JavaScript جزء النتيجة فقط دون إعادة تحميل.

تُقبل أي إجابة منطقية بنفس التسلسل. (لو الصفحة غير موجودة يظهر 404، ولو في مشكلة بالخادم 500.)
