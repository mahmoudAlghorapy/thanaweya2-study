البنية العامة لتطبيقات الويب

السؤال الرئيسي: كيف يُبنى تطبيق الويب، وكيف تعمل طبقاته الثلاث معًا للاستجابة لما يفعله المستخدم؟

ما هو تطبيق الويب؟

تطبيق الويب: تطبيق يُستخدم عادةً من خلال متصفح الويب، وقد يكون بعضه قابلًا للتثبيت على الجهاز.

أمثلة: خدمات الفيديو · التسوق · البريد الإلكتروني · الخرائط على الويب.

ملاحظة مهمة

اللي بتشوفه على الشاشة جزء بس من التطبيق؛ وراه أجزاء تانية شغالة على الخادم بتعالج البيانات وتخزّنها.

الطبقات الثلاث لتطبيق الويب

تعرض وتجمع

🖥️ الواجهة الأمامية

الدور: الجزء الذي يراه المستخدم ويتفاعل معه؛ يعرض المحتوى ويستقبل ما يكتبه أو يختاره.

أين تعمل؟ على المتصفح.

أمثلة: شاشة البحث، صفحات عرض المنتجات، نماذج الإدخال.

تقرر وتعالج

⚙️ الواجهة الخلفية

الدور: تعالج الطلبات وتطبّق قواعد التطبيق.

أين تعمل؟ على الخادم (لا يراها المستخدم).

أمثلة: البحث عن منتجات تطابق البحث، التحقق من تسجيل الدخول.

تخزّن وتسترجع

🗄️ قاعدة البيانات

الدور: تحفظ البيانات وتوفرها عند الحاجة (قواعد بيانات، ملفات، ذاكرة مخبّأة، خدمات خارجية).

أين تعمل؟ خلف الخادم.

أمثلة: معلومات المنتجات، بيانات المستخدمين، سجل الطلبات.

تشبيه: الجرسون = الواجهة الأمامية · المطبخ = الواجهة الخلفية · المخزن = قاعدة البيانات.

مثال: البحث عن منتج في متجر إلكتروني

  1. تستقبل الواجهة الأمامية كلمات البحث من المستخدم.
  2. ترسل كلمات البحث إلى الواجهة الخلفية.
  3. تطلب الواجهة الخلفية المنتجات المطابقة من قاعدة البيانات.
  4. تعيد قاعدة البيانات النتائج.
  5. تجهّز الواجهة الخلفية النتائج وترسلها.
  6. تعرض الواجهة الأمامية النتائج على الشاشة.

لاحظ: الطلب ينزل من المستخدم ← الأمامية ← الخلفية ← البيانات، والاستجابة تطلع بالعكس. الواجهة الأمامية لا تتعامل مع قاعدة البيانات مباشرة.

❓ صفحة الحجز فتحت لكن مفيش أوقات؟

المشكلة ممكن تكون في الواجهة الخلفية (لم تحسب الأوقات) أو قاعدة البيانات (لم تُرجع المواعيد) أو الاتصال بينهما.

✅ القرار الأفضل

تنظيم المسؤوليات في طبقات واضحة:

  • تحديد مكان الخطأ وإصلاحه أسهل.
  • تطوير طبقة دون إعادة بناء الباقي.

مصطلحات أساسية

  • تطبيق الويب: يُستخدم عادةً عبر متصفح الويب.
  • الواجهة الأمامية: الشاشة التي يراها المستخدمون ويتفاعلون معها.
  • الواجهة الخلفية: المعالجة الخفية من جانب الخادم.
  • قاعدة البيانات: حيث تُخزَّن البيانات وتُدار.

❓ إجابة السؤال الرئيسي (من الكتاب)

يُستخدم تطبيق الويب عادةً من خلال المتصفح، ويمكن شرح كثير من التطبيقات بنموذج مبسط من ثلاث طبقات: واجهة أمامية تعرض المحتوى وتستقبل مدخلات المستخدم، وواجهة خلفية تعالج الطلبات وتطبق قواعد التطبيق، وطبقة بيانات تحفظ البيانات وتوفرها. تنتقل الطلبات والنتائج بين هذه الأجزاء لتنفيذ مهمة المستخدم. وهذا نموذج للتعلم وليس بنية إلزامية لكل تطبيق: فقد تختلف البنية، وقد لا توجد قاعدة بيانات تقليدية أصلًا.

📝 اختبر نفسك — الدرس 3-1

  1. في تطبيق الطقس: سمِّ الطبقة المسؤولة عن: أخذ اسم المدينة – البحث عن بيانات التوقعات – تخزين التوقعات السابقة.
  2. حدد الطبقة في شبكة تواصل: شاشة الخط الزمني – معالجة تحديد الجمهور – تخزين علاقات المتابعة – معالجة الإشعارات.
  3. لماذا لا يمكن للواجهة الأمامية وحدها أن تعرض نتائج بحث صحيحة؟
✔️ اعرض الإجابات
  1. الأمامية – الخلفية – قاعدة البيانات.
  2. أمامية – خلفية – قاعدة بيانات – خلفية.
  3. لأن البيانات في قاعدة البيانات، والبحث فيها مهمة الواجهة الخلفية على الخادم.
3-2

طرق اتصال تطبيقات الويب

السؤال الرئيسي: كيف يتواصل العميل والخادم لتشغيل تطبيق الويب، وما القواعد والرسائل التي يستخدمانها؟

العميل والخادم — نموذج الطلب والاستجابة

العميل (Client): برنامج أو جهاز يرسل طلبًا إلى خدمة أخرى؛ الجانب الذي يطلب البيانات أو المعالجة. مثل: المتصفح، تطبيق الهاتف.

الخادم (Server): الجانب الذي يستقبل الطلبات من العملاء، ويعالجها، ويعيد الاستجابات. مثل: خادم الويب، خادم التطبيقات.

الطلب: «أرني هذه الصفحة» ← الاستجابة: إعادة البيانات المطلوبة. تعتمد كثير من تطبيقات الويب على إرسال العميل طلبًا وإعادة الخادم استجابة، وتحدد بروتوكولات مثل HTTP قواعد هذا التبادل.

🔓 غير مشفّر

HTTP — بروتوكول نقل النص التشعبي

  • بروتوكول يُستخدم لتبادل الرسائل بين عميل وخادم على الويب.
  • لا يشفّر المحتوى؛ المتجسس يمكنه قراءته.
  • العنوان يبدأ بـ http://
🔒 آمن

HTTPS — HTTP عبر اتصال TLS آمن

  • استخدام HTTP عبر اتصال TLS (Transport Layer Security) آمن.
  • يحمي سرية الاتصال وسلامته، ويصادق على الخادم.
  • العنوان يبدأ بـ https://

ليه صفحة تسجيل الدخول لازم تكون HTTPS؟

لأن اسم المستخدم وكلمة المرور بيتبعتوا عبر الشبكة؛ ولو HTTP عادي ممكن أي متجسس (مثلًا على Wi-Fi عام) يقرأهم أو يعدّلهم. في HTTPS بيحمي TLS المحتوى ويتأكد من هوية الخادم.

ربط بالوحدة الثانية: TLS هو نفس الاتصال الآمن اللي درسته في «تقنيات التشفير والمصادقة».

طريقة طلب HTTP: GET و POST

طريقة طلب HTTP: معلومات في الطلب المرسل من العميل إلى الخادم توضح «نوع العملية المطلوبة».

GET — «هات»

يُستخدم عادةً لطلب مورد أو بيانات من الخادم.

أمثلة: عرض صفحة ويب · نتائج البحث · توقعات الطقس.

POST — «خد»

يُستخدم عادةً لإرسال بيانات ليعالجها الخادم.

أمثلة: بيانات تسجيل الدخول · محتويات نموذج.

request.http
# الطلب: العميل يطلب نتائج البحث
GET /search?q=laptop HTTP/1.1
Host: shop.example.com

# الاستجابة: الخادم يرد
HTTP/1.1 200 OK
Content-Type: application/json

السطر الثاني طلب GET، والسطر قبل الأخير استجابة برمز الحالة 200 (للتوضيح فقط).

رموز حالة HTTP

رمز حالة HTTP: رقم في الاستجابة المرسلة من الخادم إلى العميل يشير إلى نتيجة المعالجة.

الرمزالمعنىالشرحمثال
200نجاحتمت معالجة الطلب بنجاحالصفحة فتحت عادي
404غير موجودالمورد المطلوب غير موجود بهذا العنوانرابط غلط أو صفحة اتمسحت
500خطأ في الخادمخطأ داخلي في الخادم منعه من إكمال الطلبالموقع «واقع» من عندهم

انتبه: في 404 المشكلة غالبًا في العنوان المطلوب، أما 500 فالمشكلة في جانب الخادم، والرمز وحده لا يحدد السبب التفصيلي.

واجهة برمجة التطبيقات (API) وصيغة JSON

API (Application Programming Interface): مجموعة قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر؛ «عقد» محدد للتواصل بين البرمجيات.

JSON (JavaScript Object Notation): صيغة نصية شائعة لتمثيل وتبادل البيانات المهيكلة باستخدام كائنات ومصفوفات وقيم بسيطة، تدعمها لغات كثيرة.

قد ترسل الواجهة الأمامية طلبات إلى خدمة خلفية عبر API وتستقبل منها البيانات، غالبًا بصيغة JSON.

weather.json
{
  "city": "Cairo",
  "temperature": 31
}
المفتاح (key)القيمة (value)
"city""Cairo"
"temperature"31

أمثلة تطبيقية على الاتصال

🌦️ تطبيق الطقس

يطلب تطبيق الطقس من API خدمة الطقس توقعات اليوم:

  • الطريقة: GET لأنه يسترجع بيانات.
  • البروتوكول: HTTPS لحماية الاتصال من التلاعب والتجسس والتأكد أن الخادم حقيقي.
  • ميزة JSON: منظمة وسهلة القراءة وتدعمها لغات كثيرة، فيسهل استخراج درجة الحرارة وعرضها.
مثال: نظام مدرسة
الإجراءالأسلوبملاحظة
تحميل سجل درجات الطالبGETاسترجاع بيانات
إرسال نموذج تسجيل الدخولPOSTإرسال بيانات للمعالجة، عبر HTTPS
طلب الجدول الدراسي من نظام مدرسة أخرىGETيتضمن API لأنه تواصل بين برنامجين

الفكرة الرئيسية: يطلب العميل ويستجيب الخادم، باستخدام بروتوكول (HTTP/HTTPS)، وطريقة طلب (GET/POST)، ورمز حالة، وغالبًا API تعيد البيانات بصيغة JSON.

❓ إجابة السؤال الرئيسي (من الكتاب)

في كثير من الحالات يرسل العميل طلبًا ويعيد الخادم استجابة وفق قواعد HTTP، وقد تستخدم التطبيقات وسائل اتصال أخرى عند الحاجة. يحدد HTTP طريقة تبادل الرسائل، ويستخدم HTTPS اتصال TLS آمنًا. وتوضح طريقة طلب HTTP الغرض من الطلب: GET عادةً لطلب مورد أو بيانات، وPOST لإرسال بيانات ليعالجها الخادم. وتبيّن رموز الحالة نتيجة معالجة الطلب. وقد تستخدم التطبيقات واجهة برمجة تطبيقات (API) وقواعد واضحة لتبادل البيانات، وربما تمثلها بصيغة JSON النصية المهيكلة.

📝 اختبر نفسك — الدرس 3-2

  1. حدد GET أو POST: عرض صفحة ويب – إرسال اسم المستخدم وكلمة المرور – عرض نتائج البحث – إرسال نموذج التواصل.
  2. أي تركيبة غير صحيحة: (أ) 200 نجاح (ب) 404 المورد غير موجود (ج) 500 تمت المعالجة بنجاح (د) 500 مشكلة في جانب الخادم؟
  3. أكمل: الاتصال بين (....) الذي يرسل طلبًا و(....) الذي يعيد استجابة، ويُستخدم بروتوكول (....)، ويسمى استخدامه عبر TLS آمن (....).
✔️ اعرض الإجابات
  1. GET – POST – GET – POST.
  2. (ج).
  3. العميل – الخادم – HTTP – HTTPS.

أساسيات تقنية الواجهة الأمامية

السؤال الرئيسي: كيف تعمل HTML وCSS وJavaScript معًا لبناء صفحة ويب، وما الذي يجعل الواجهة الأمامية الحديثة ذات معنى وقابلة للتكيف؟

البنية

HTML

يحدد بنية (هيكل) صفحة الويب؛ يصف العناوين والفقرات والصور والروابط.

التشبيه: هيكل المبنى.

المظهر

CSS

يحدد مظهر الصفحة: الألوان، التخطيط، الحجم، الخطوط.

التشبيه: الديكور الداخلي والخارجي.

السلوك

JavaScript

يضيف السلوك والتفاعلية: الاستجابة للأزرار وتحديث جزء فقط من الشاشة.

التشبيه: أنظمة الكهرباء والسباكة.

ليس ضروريًا أن تستخدم الصفحة الثلاث معًا: يمكن HTML وحده، أو HTML مع CSS وJavaScript حسب الوظائف المطلوبة. صفحة الويب الحديثة تركيبة، وليست تقنية واحدة.

مثال متدرّج: صفحة «الكتب التي أحبها»

الخطوة الأولى: الهيكل بـ HTML

index.html
<h1>صفحتي على الويب</h1>
<p>هذه صفحة بسيطة عن كتبي المفضلة.</p>
<h2>الكتب التي أحبها</h2>
<ul>
  <li>كتاب أ</li>
  <li>كتاب ب</li>
</ul>
<button id="likeBtn">أعجبني</button>
<span id="count">0</span>
  • عنوان رئيسي h1 وفقرة p.
  • عنوان فرعي h2 وقائمة ul فيها عناصر li.
  • زر وعدّاد لكل منهما id لنستخدمه لاحقًا.

المحتوى موجود، لكن الشكل بسيط وبدون تفاعل. الخطوة التالية: CSS ثم JavaScript.

الخطوة الثانية: التنسيق بـ CSS (ألوان وخطوط)

style.css
h1 {
  color: navy;
  font-size: 32px;
}
body { background-color: #f5f5f5; }
button {
  background-color: black;
  color: white;
}

الخطوة الثالثة: السلوك بـ JavaScript (عدّاد يزيد عند الضغط)

script.js
let likes = 0;
document.getElementById("likeBtn")
  .onclick = function () {
    likes = likes + 1;
    document.getElementById("count")
      .textContent = likes;
  };

لاحظ: JavaScript حدّث جزءًا فقط من الشاشة (الرقم) وليس الصفحة كلها. الكود للتوضيح؛ المطلوب في الامتحان فهم دور كل تقنية.

HTML الدلالي (Semantic HTML)

التعريف: استخدام عناصر توضح وظيفة أجزاء الصفحة: header أعلى الصفحة، nav للتنقل، main للمحتوى الرئيسي، footer أسفل الصفحة.

layout.html
<!-- غير دلالي: صناديق لا توضح وظيفتها -->
<div>شعار الموقع</div>
<div>الرئيسية | الأخبار</div>
<div>نص الخبر...</div>

<!-- دلالي: اسم العنصر يقول وظيفته -->
<header>شعار الموقع</header>
<nav>الرئيسية | الأخبار</nav>
<main>نص الخبر...</main>

  1. إمكانية الوصول: يساعد قارئ الشاشة على فهم بنية الصفحة والتنقل فيها. (إمكانية الوصول = Accessibility: تصميم المحتوى والواجهة بحيث يستطيع أصحاب القدرات والاحتياجات المختلفة استخدامها، بمن فيهم ذوو الإعاقة.)
  2. فهم محركات البحث: قد يساعد محركات البحث على فهم المحتوى، لكنه لا يضمن ترتيبًا أعلى.

تنبيه امتحاني: HTML الدلالي لا يجعل الصفحة أسرع بالضرورة، ولا يضمن الترتيب الأول في البحث.
SEO: ممارسات تجعل الصفحة أيسر في الفهرسة والظهور في نتائج البحث.

التصميم المتجاوب (Responsive Design)

التعريف: مفهوم تصميمي يُضبط فيه التخطيط تلقائيًا وفقًا لأحجام الشاشات المختلفة مثل الكمبيوتر والهواتف الذكية والأجهزة اللوحية.

فائدته: يساعد الصفحة على التكيف مع أحجام الشاشات وتحسين سهولة استخدامها.

نهج الأولوية للجوال: لأن كثيرًا من الناس يستخدمون الويب عبر الهواتف، يراعي المطورون الشاشات الصغيرة منذ بداية التصميم.

.products { grid-template-columns: repeat(4, 1fr); }
@media (max-width: 600px) {
  .products { grid-template-columns: 1fr; }
}

💡 الصفحة دي نفسها متجاوبة: صغّر نافذة المتصفح أو افتحها من الموبايل وشوف الكروت بتترتب إزاي.

أطر العمل والمكتبات

إطار العمل: بنية توفر مسبقًا وظائف ومكونات شائعة الاستخدام، لجعل تطوير تطبيقات الويب أكثر كفاءة؛ فلا يحتاج المطورون إلى كتابة كل الكود من الصفر، ويبنون الصفحات من مكوّنات قابلة لإعادة الاستخدام.

React

مكتبة JavaScript لبناء واجهات المستخدم من مكونات قابلة لإعادة الاستخدام، وتحديثها عند تغير البيانات.

Vue

إطار بسيط له بنية بسيطة ويتيح بناء تطبيقات الويب تدريجيًا بدءًا من ميزات صغيرة.

Next.js

إطار مبني على React يوفر التوجيه وطرقًا مختلفة لعرض الصفحات والعمل على الخادم والعميل.

مثال للمكوّن: في متجر تصمم «بطاقة منتج» واحدة (صورة + اسم + سعر + زر شراء) وتستخدمها لألف منتج بدل ما تكتب الكود ألف مرة.

فكّر كمهندس: صفحة نادٍ طلابي

نادٍ طلابي يريد صفحة تعرض فعالياته، منسقة بألوان النادي، وفيها زر يعرض عدد المسجلين.

المطلوبالتقنية
قائمة الفعالياتHTML

قراءة أسهل على الهاتفالتصميم المتجاوب

القرار الأفضل: استخدام HTML وCSS وJavaScript كلٌّ حسب دوره بدل ملف واحد: التعديل أسهل (تغيير الألوان دون لمس المحتوى)، وتنظيم أوضح واكتشاف أسرع للأخطاء.

❓ إجابة السؤال الرئيسي (من الكتاب)

تستخدم كثير من صفحات الويب HTML لبناء الهيكل، ويمكن أن تضيف CSS للمظهر وJavaScript للتفاعل بحسب الحاجة. ويستخدم HTML الدلالي عناصر توضح وظيفة أجزاء الصفحة، ما يساعد التقنيات المساعدة ومحركات البحث على فهم بنيتها. ويجعل التصميم المتجاوب الصفحة تتكيف مع أحجام الشاشات المختلفة. كما تساعد المكتبات والأطر على بناء الواجهة من مكونات قابلة لإعادة الاستخدام وتقليل العمل المتكرر: فـReact مكتبة لبناء واجهات المستخدم، وNext.js إطار مبني عليها لبناء تطبيقات ويب.

📝 اختبر نفسك — الدرس 3-3

  1. ما الاختصار من 4 أحرف للتقنية التي تحدد بنية الصفحة؟ ومن 3 أحرف للتي تحدد مظهرها؟
  2. أي مما يلي لا يمثل فائدة لـ HTML الدلالي: (أ) قارئ الشاشة يفهم البنية (ب) محركات البحث تفهم المحتوى (ج) عرض الصفحة أسرع بالضرورة (د) إيصال المعلومات لذوي الإعاقة البصرية؟
  3. لماذا نحتاج التصميم المتجاوب؟
